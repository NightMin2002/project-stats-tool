## 🎯 模块职责划分

### 1. **配置层** (`config.js`)
- ✅ 集中管理所有配置项
- ✅ 语言映射定义
- ✅ `.gitignore` 规则加载
- ✅ 统计数据结构初始化

### 2. **工具层** (`utils/`)
- ✅ **formatters.js**: 数字、文件大小格式化
- ✅ **file-utils.js**: 文件类型判断、路径处理

### 3. **分析层** (`analyzers/`)
- ✅ **text-analyzer.js**: 中文字符、英文单词统计
- ✅ **code-analyzer.js**: 代码行类型分析
- ✅ **file-analyzer.js**: 单文件完整分析

### 4. **核心层** (`core/`)
- ✅ **project-scanner.js**: 递归目录扫描
- ✅ **stats-calculator.js**: 复杂度计算、Tokens估算、项目类型检测

### 5. **生成层** (`generators/`)
- ✅ **tree-generator.js**: 目录树、文件树生成
- ✅ **text-generator.js**: Markdown、文件列表、文字提取
- ✅ **html-generator.js**: HTML可视化报告
- ✅ **output-manager.js**: 统一的文件保存管理

### 6. **入口层** (`project-stats.js`)
- ✅ 协调所有模块
- ✅ 控制执行流程
- ✅ 控制台输出
- ✅ 简洁清晰 (267 行)

## 🌟 核心优势

### 1. **单一职责原则**
每个模块专注于一个明确的功能，代码更易理解和维护。

### 2. **高度可测试**
独立模块可以单独测试，不依赖整个系统。

### 3. **易于扩展**
新增功能只需创建新模块或扩展现有模块，不影响其他部分。

### 4. **清晰的依赖关系**
```
入口层 (project-stats.js)
  ↓
生成层 (generators/)
  ↓
核心层 (core/) + 分析层 (analyzers/)
  ↓
工具层 (utils/) + 配置层 (config.js)
```

### 5. **向后兼容**
旧版本已备份为 [`src/project-stats-old.js.bak`](../src/project-stats-old.js.bak:1)，可随时回退。

## 🛠️ 维护建议

### 添加新功能
```javascript
// 1. 在对应目录创建新模块
src/analyzers/new-analyzer.js

// 2. 导出功能
module.exports = { analyzeNewFeature };

// 3. 在主入口引入
const { analyzeNewFeature } = require('./analyzers/new-analyzer');

// 4. 在适当位置调用
analyzeNewFeature(stats, config);
```

### 修复 Bug
1. 定位到负责该功能的模块
2. 在该模块内修复
3. 无需担心影响其他功能

### 性能优化
1. 使用性能分析工具定位瓶颈模块
2. 单独优化该模块
3. 通过单元测试验证优化效果
